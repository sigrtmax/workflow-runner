# Состояние реализации

Реализованы NestJS API и отдельный BullMQ worker, четыре типа шагов, неизменяемые
версии процессов и сохранение исполнения в PostgreSQL. Redis содержит уведомления;
состояние графа, попытки, сроки и журнал остаются в БД.

Проверки используют отдельные реальные PostgreSQL-базы, Redis-префиксы, локальный
HTTP-стенд и дочерние worker-процессы. Покрыты:

- одновременный идемпотентный запуск, конфликт содержания и версии;
- захват, heartbeat, устаревший token и общий лимит нескольких worker;
- гонка незавершённого heartbeat с новым захватом;
- атомарная фиксация результата, истории попытки, журнала и готовности потомка;
- параллельные ветки, слияние один раз, пропуск невыбранных узлов;
- `SIGKILL` после приёма HTTP-запроса, повтор с прежним ключом и trace ID;
- восстановление очереди и сохранённого срока задержки;
- pause во время HTTP-запроса, resume, повтор только упавших шагов;
- ограничение повторов, backoff, timeout и неопределённый внешний результат;
- безопасная валидация JSON до преобразования DTO и совместимость с JSONB;
- курсорная пагинация журнала с числовым порядком ID;
- экспорт OTLP, длительность задержки, ошибки по шагам и состав логов.

Команды общей проверки: `npm run format:check`, `npm run lint`,
`npm run typecheck`, `npm run build`, `npm test -- --runInBand`.
Для интеграционных тестов предварительно нужен тестовый Compose из README.
Последняя общая проверка: все пять команд завершились с кодом 0;
15 тестовых наборов, 116 тестов прошли.

Границы: нет публичной авторизации, визуального конструктора, произвольного кода,
циклов, компенсаций и входящих callback. Идемпотентность внешнего эффекта требует
поддержки получателя. Аварийно оборванная телеметрия может теряться; журнал БД
сохраняет факты переходов. Произвольные реальные CRM/ERP и публичное развёртывание
не проверялись.

`npm audit` после обновления транзитивных зависимостей не обнаруживает известных
уязвимостей. API использует простой query parser и JSON body parser; расширенный
разбор query и form-urlencoded отключён.
