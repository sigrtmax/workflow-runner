# HTTP API

Все маршруты локальные, JSON. Максимальное тело запроса — 256 KiB, лимит запросов —
120 в минуту на IP в одном API-процессе. Неизвестные поля верхнего уровня отклоняются.
Установленный клиентом `X-Request-Id` принимается, если содержит 1–64 латинских букв,
цифр, `_` или `-`; иначе создаётся новый. Идентификатор возвращается в заголовке.

| Метод и путь                             | Запрос                                                                    | Успех                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `POST /workflows/:name/versions`         | `{version, definition: {steps}}`                                          | `201`: `{id, name, version, definition}`                       |
| `GET /workflows/:name/versions/:version` | —                                                                         | `200`: опубликованная версия                                   |
| `POST /executions`                       | `{workflowName, version, input}`, заголовок `Idempotency-Key`             | `201`: `{id, created: true}`; повтор — `200`, `created: false` |
| `GET /executions/:id`                    | —                                                                         | `200`: состояние и результаты шагов                            |
| `GET /executions/:id/events`             | `after` — ID события, по умолчанию `0`; `limit` — 1–100, по умолчанию 100 | `200`: массив событий по возрастанию ID                        |
| `POST /executions/:id/pause`             | —                                                                         | `200`: состояние                                               |
| `POST /executions/:id/resume`            | —                                                                         | `200`: состояние                                               |
| `POST /executions/:id/retry`             | `{confirmUnknownOutcome?: boolean}`                                       | `200`: состояние                                               |

Имя процесса и ID шага: `[a-z][a-z0-9_]{0,63}`; версия — целое от 1 до 2147483647.
Execution ID — UUID v4. Ключ запуска — 1–128 печатных ASCII-символов без пробелов.
`input` обязателен; допускается любой JSON, включая `null`, с вложенностью до 32.
Определение ограничено 100 узлами и вложенностью JSON до 32.

Состояние исполнения содержит `id`, `workflowName`, `version`, `status`, `input`,
`createdAt`, `finishedAt` и `steps`. У шага — `id`, `status`, `output`, `attemptCount`,
`error`. `output: null` может быть результатом или отсутствием результата — это
различается по состоянию. Lease и внутренние токены API не возвращает.

Событие содержит строковый `id`, `stepId` (либо `null`), `kind`, `detail`, `createdAt`.
Следующая страница использует последний полученный ID как `after`.
Время передаётся в ISO 8601. Журнал сохраняет прежние попытки после ручного retry.

Ошибка имеет вид `{code, message, requestId}`: `400` — неверный запрос или граф,
`404` — отсутствующий ресурс, `409` — конфликт версии, ключа или перехода,
`413` — превышен размер тела, `429` — лимит запросов, `500` — внутренняя ошибка.
Текст внутренних исключений и ответы интеграций в HTTP-ошибку не включаются.

`pause`/`resume` повторяемы в соответствующем состоянии; успешное выполнение они
не оживляют. После окончательной ошибки новые шаги не запускаются. Уже захваченные
могут завершиться. `retry` разрешён после их завершения или восстановления lease
и сбрасывает только упавшие узлы с новым бюджетом повторов, сохраняя вход и версию.
Подтверждение требуется при неопределённом результате unsafe HTTP и неожиданном
успешном HTTP-статусе: внешний эффект мог уже произойти.

Описание четырёх шагов и ветвления — в [design.md](design.md), готовое тело публикации —
в [lead-to-erp.json](../examples/lead-to-erp.json). HTTP-результат сохраняется как
`{status, body}`; пустое тело — `null`. Тело должно быть корректным JSON, включая JSON-строку. Сохранённый результат ограничен 1 MiB и вложенностью 32; NUL и непарные суррогаты Unicode отклоняются. Секреты
и настоящие персональные данные не следует включать в демонстрационные входы.
